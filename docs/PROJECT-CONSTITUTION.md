# Constitución del proyecto — Mi Lugar

## 1. Propósito
Crear una experiencia digital turística de San Patricio del Chañar que haga que visitantes y habitantes puedan descubrir lugares, historias, personas, paisajes, cultura y posibilidades de recorrido con una interfaz extremadamente sencilla y una arquitectura interna preparada para crecer.

## 2. Ley central
> La complejidad pertenece al sistema; la simplicidad pertenece a la persona.

Nunca trasladaremos la complejidad técnica o editorial al visitante.

## 3. Identidad
El proyecto debe sentirse:
- cercano
- local
- cuidado
- contemporáneo
- ilustrado
- editorial
- humano
- profesional

No debe sentirse:
- institucional por obligación
- corporativo
- bancario
- videojuego
- portal de noticias
- catálogo frío de atractivos

## 4. Verdad territorial
No se inventan lugares, actividades, servicios, horarios, precios, datos históricos, transporte, estadísticas, testimonios ni relaciones.

Cuando un dato no está verificado, no se presenta como hecho.

Cada contenido relevante debe poder conservar procedencia y estado de verificación.

## 5. Contenido
Entidades previstas:
- lugar
- historia
- persona
- paisaje
- experiencia
- recorrido
- evento
- fotografía
- documento
- video
- institución
- producto local

Las entidades pueden relacionarse entre sí.

## 6. Experiencia
La primera pantalla debe ofrecer pocas decisiones claras.

El visitante podrá profundizar progresivamente:
1. descubrir
2. explorar
3. conocer
4. profundizar
5. relacionar

La profundidad nunca debe ser obligatoria.

## 7. Diseño
La fotografía real tiene protagonismo.

La ilustración construye identidad y acompaña al contenido.

El color sirve para orientar y emocionar, no para decorar sin propósito.

Las animaciones son suaves y funcionales.

## 8. Mobile first
El diseño se prueba primero en 320 px, 390 px y 430 px, y luego en escritorio.

## 9. Compartir
Cada contenido importante debe poder tener una ruta estable y una presentación adecuada para compartir.

## 10. Programación
Preferir arquitectura simple, modular, estática y mantenible.

No introducir dependencias o servicios externos innecesarios.

## 11. Publicación
El proyecto se desarrolla en este repositorio y se prepara para GitHub Pages.

No se agregan caminos paralelos de Vercel.

## 12. Regla de oro
> Que se note que fue hecho por gente que ama Chañar, sin convertir el sitio en propaganda de Chañar.
